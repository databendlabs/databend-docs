Use [COPY INTO](/sql/sql-commands/dml/dml-copy-into-table) to load files from an object storage bucket into Databend. Start here for SQL loading from Amazon S3. This tutorial uses a Parquet sample file. For other formats, see [Input & Output File Formats](/sql/sql-reference/file-format-options).

**Task flow:** [Prepare S3 data](#prepare-s3-data) → [Choose authentication](#authentication) → [Connect and verify](#connect-to-s3) → [Load the sample data](#load-sample-data).

:::note
This tutorial covers SQL loading. For scheduled loading through the Cloud console, see [Amazon S3 Integration Task](/guides/cloud/data-integration/s3). For S3 event notifications, see [Amazon SQS (S3) Integration Task](/guides/cloud/data-integration/sqs-s3).
:::

## Prepare Your S3 Data {/* #prepare-s3-data */}

<span id="tutorial-loading-from-amazon-s3-bucket" />
<span id="before-you-begin" />

Prepare these items before you configure access:

- An S3 bucket and its AWS Region. This tutorial uses `databend-toronto` in `us-east-2`. Replace these values with your own values.
- AWS permissions for your chosen authentication method. IAM Role needs policies and roles. Access Keys needs a policy, an IAM user, and an access key. Ask your AWS administrator to perform these tasks if needed. Do not use AWS root user access keys.
- Databend permissions to create a [Connection](/sql/sql-commands/ddl/connection/create-connection), a [Stage](/sql/sql-commands/ddl/stage/ddl-create-stage), and a [table](/sql/sql-commands/ddl/table/ddl-create-table).

Download [books.parquet](https://datafuse-1253727613.cos.ap-hongkong.myqcloud.com/data/books.parquet). The file contains two records:

```text title='books.parquet'
Transaction Processing,Jim Gray,1992
Readings in Database Systems,Michael Stonebraker,2004
```

Upload the file to `load/books.parquet` in your bucket. Keep the object private. You do not need to disable S3 Block Public Access.

For the AWS tasks, see [Creating a bucket](https://docs.aws.amazon.com/AmazonS3/latest/userguide/create-bucket-overview.html) and [Uploading objects](https://docs.aws.amazon.com/AmazonS3/latest/userguide/upload-objects.html).

## Choose an Authentication Method {/* #authentication */}

Configure one authentication method. Both methods use the same Stage, verification queries, and loading SQL below.

| Method | When to use it | Setup and next task |
|--------|----------------|---------------------|
| **IAM Role (recommended for Databend Cloud)** | Use temporary AWS credentials without storing access keys in Databend. | Complete [AWS IAM Role authorization](/guides/cloud/security/iam-role/aws). Then return to [Create a Connection and Stage](#connect-to-s3) and select **IAM Role**. |
| **Access Keys** | Use an IAM user's access key when role-based access is not suitable for your deployment. | Complete [Configure Access Keys](#access-keys). Then select **Access Keys** in [Create a Connection and Stage](#connect-to-s3). |

A [Connection](/sql/sql-commands/ddl/connection/create-connection) stores reusable authentication parameters. A Stage specifies the S3 location. Creating a Connection is not a separate AWS authentication method.

## Configure Access Keys {/* #access-keys */}

Skip this task if you use IAM Role. If you already have a suitable IAM user and access key, continue with [Create a Connection and Stage](#connect-to-s3).

### Create a Read-Only Permissions Policy

In the [AWS IAM console](https://console.aws.amazon.com/iam/), open **Policies → Create policy → JSON**.

Paste the following policy into the editor. Replace `databend-toronto` and `load/` with your bucket and prefix. Save the policy as `databend-s3-user-read`.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "GetBucketRegion",
      "Effect": "Allow",
      "Action": "s3:GetBucketLocation",
      "Resource": "arn:aws:s3:::databend-toronto"
    },
    {
      "Sid": "ListLoadPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::databend-toronto",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["load/", "load/*"]
        }
      }
    },
    {
      "Sid": "ReadLoadObjects",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::databend-toronto/load/*"
    }
  ]
}
```

This policy allows listing and reading only the specified prefix. It does not permit uploads or deletes. For KMS-encrypted objects or write access, see [Additional Permissions](/guides/cloud/security/iam-role/aws#additional-permissions).

### Create an IAM User {/* #create-an-iam-user-and-access-key */}

In the IAM console, open **Users → Create user**. Use these settings:

| Setting | Value |
|---------|-------|
| User name | `databend-s3-reader` |
| AWS Management Console access | Disabled |
| Permissions | **Attach policies directly** → `databend-s3-user-read` |

Review the settings. Select **Create user**.

### Create and Store an Access Key

On the user's details page, open **Security credentials → Access keys → Create access key**.

Select **Third-party service** as the use case. Complete the wizard to create the key. Store the **Access key ID** and **Secret access key** in your approved secret manager.

:::warning
AWS shows the secret access key only when you create it. Do not put real keys in screenshots, source control, support tickets, or shared SQL examples. SQL clients and worksheets can retain statement text. Follow your organization's secret-handling rules when you enter credentials.
:::

## Create a Connection and Stage {/* #connect-to-s3 */}

<span id="step-1-create-a-connection-and-stage" />

Open a Databend Cloud worksheet or connect with [BendSQL](/guides/connect/sql-clients/bendsql). Select your authentication method below. Replace its example values with your own configuration.

<Tabs groupId="s3-authentication">
<TabItem value="iam-role" label="IAM Role" default>

Use **your customer IAM role ARN** and the matching external ID from [AWS IAM Role authorization](/guides/cloud/security/iam-role/aws). Do not use the Databend Cloud principal ARN as `ROLE_ARN`.

```sql
CREATE CONNECTION s3_books_conn
    STORAGE_TYPE = 's3'
    ROLE_ARN = 'arn:aws:iam::987654321987:role/databend-docs-s3-role'
    EXTERNAL_ID = 'my-external-id-123'
    REGION = 'us-east-2';
```

</TabItem>
<TabItem value="access-keys" label="Access Keys">

Use the IAM user's access key values from [Configure Access Keys](#access-keys).

```sql
CREATE CONNECTION s3_books_conn
    STORAGE_TYPE = 's3'
    ACCESS_KEY_ID = '<your-access-key-id>'
    SECRET_ACCESS_KEY = '<your-secret-access-key>'
    REGION = 'us-east-2';
```

</TabItem>
</Tabs>

Create one Stage for the authorized prefix. This SQL is the same for both authentication methods:

```sql
CREATE STAGE s3_books_stage
    URL = 's3://databend-toronto/load/'
    CONNECTION = (CONNECTION_NAME = 's3_books_conn');
```

Keep the trailing `/` in the Stage URL. The AWS policy enforces the access scope. The Connection name and Stage URL alone do not restrict the credentials to that path.

## Verify S3 Access {/* #verify-s3-access */}

<span id="step-2-verify-s3-access" />

List the files in the Stage:

```sql
LIST @s3_books_stage;
```

The result should include `books.parquet`. Read the file to check object access:

```sql
SELECT title::VARCHAR AS title,
       author::VARCHAR AS author,
       date::VARCHAR AS date
FROM @s3_books_stage/books.parquet
LIMIT 2;
```

The result should contain the two sample records. Listing checks `s3:ListBucket`. Reading also checks `s3:GetObject` and any required KMS decryption access. Fix authentication or permissions errors before you load data.

For role assumption errors, see [IAM Role Troubleshooting](/guides/cloud/security/iam-role/aws#troubleshooting). For other errors, see [Troubleshooting](#troubleshooting) below.

## Load the Sample Data {/* #load-sample-data */}

<span id="step-1-create-target-table" />
<span id="step-3-create-target-table" />

Create a test table in a database where you have the required privileges:

```sql
CREATE TABLE books
(
    title VARCHAR,
    author VARCHAR,
    date VARCHAR
);
```

### Copy and Check the Rows {/* #step-4-copy-data-into-table */}

<span id="step-2-copy-data-into-table" />

Load only the sample file. Keep source file deletion disabled:

```sql
COPY INTO books
FROM @s3_books_stage
FILES = ('books.parquet')
FILE_FORMAT = (TYPE = 'PARQUET')
PURGE = FALSE;
```

Check the loaded data:

```sql
SELECT * FROM books ORDER BY title;
```

Expected records:

```text
title                       |author             |date|
----------------------------+-------------------+----+
Readings in Database Systems|Michael Stonebraker|2004|
Transaction Processing      |Jim Gray           |1992|
```

## Troubleshooting {/* #troubleshooting */}

| Symptom | What to check |
|---------|---------------|
| `AssumeRole` fails or STS returns `AccessDenied` | Check the role ARN, trusted Databend principal, and external ID. See [IAM Role Troubleshooting](/guides/cloud/security/iam-role/aws#troubleshooting). |
| `InvalidAccessKeyId` or `SignatureDoesNotMatch` | Check the access key ID and secret access key. Confirm that the key is active. Do not add whitespace when you copy the values. |
| `LIST` returns `AccessDenied` | Check `s3:ListBucket` on the bucket ARN and the `s3:prefix` condition. Check for explicit denies in bucket, organization, or endpoint policies. |
| Listing succeeds, but reading fails | Check `s3:GetObject` on the object ARN. For KMS-encrypted objects, check `kms:Decrypt` and the KMS key policy. |
| No files appear | Check that the file is at `load/books.parquet` and the Stage URL ends in `/load/`. |
| An endpoint or Region error occurs | Set `REGION` to your bucket's AWS Region. |
| SQL reports insufficient privileges | Check the current Databend role and its Connection, Stage, or table privileges. These privileges are separate from AWS permissions. |

## Rotate Credentials or Clean Up {/* #cleanup */}

<span id="rotate-credentials-or-clean-up" />

Stages usually copy Connection parameters at creation. Replacing a Connection does not update those stored parameters. When you change the role, external ID, or access keys, recreate the affected Stages with the new Connection parameters. Verify access before you revoke the old configuration. See [CREATE CONNECTION](/sql/sql-commands/ddl/connection/create-connection).

To remove the Databend test objects, run:

```sql
DROP TABLE books;
DROP STAGE s3_books_stage;
DROP CONNECTION s3_books_conn;
```

These commands do not delete S3 objects, deactivate AWS keys, or revoke IAM role access. Remove test-only AWS resources separately. For role revocation, see [Maintain or Remove Access](/guides/cloud/security/iam-role/aws#maintain-or-remove-access).
